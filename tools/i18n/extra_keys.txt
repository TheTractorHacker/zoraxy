Rate limit 120 requests per minute per IP
A starting point, review it before use. Enable a rate limit on every public site: 120 requests per minute per client IP (a burst of 120 is allowed, then 2 per second). Rate limiting protects availability, not accounts; the numbers are starting points, adjust them from the 429 count in the statistics.
Strict limit of 5 requests per minute per IP on /login, /signin, /wp-login.php and /auth
A starting point, review it before use. 5 attempts per minute per IP (burst 5) on the usual login paths; the rest of the site is not limited by this preset. Add other login paths under Path rules. Account-level protection is needed in the app itself (lockout, MFA, password policy): an attacker with many addresses is not slowed down by a per IP limit. Rate limiting protects availability, not accounts; the numbers are starting points, adjust them from the 429 count in the statistics.

Rate limit 300 requests per minute per IP with bursts, 10 per minute on /web/login, WebSocket cap
A starting point, review it before use. 300 requests per minute per client IP with a burst of 600, because Odoo loads many small requests. Rate limiting protects availability, not accounts; the numbers are starting points, adjust them from the 429 count in the statistics.
Rate limit 120 requests per minute per API key (Authorization header), per IP when there is none
A starting point, review it before use. 120 requests per minute per client, where the client is the Authorization header (hashed in memory, never logged); a request without one is counted per IP. To key by another header such as X-API-Key, change the key in the Rate limit card. A per IP guard of 10 times the limit stops clients from inventing keys. Prefer API-key based limits to IP based ones, but keys must be issued and checked by the API itself. Rate limiting protects availability, not accounts; the numbers are starting points, adjust them from the 429 count in the statistics.

WebSocket on, at most 20 concurrent connections per IP, handshakes not counted in the request limit
A starting point, review it before use. WebSockets are limited by the number of concurrent connections per client IP (20), not by the HTTP request limit: a handshake is not counted against it and frames inside a connection are never counted. Raise the cap when many users share one address. Rate limiting protects availability, not accounts; the numbers are starting points, adjust them from the 429 count in the statistics.
