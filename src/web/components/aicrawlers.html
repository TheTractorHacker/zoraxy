AI crawlers

Decide which AI crawlers may read your sites. Pick an action for each purpose (training, search, user-triggered fetch) or for one crawler, and override it for a single site. It is off until you turn it on, and a crawler without a policy is handled exactly as before.

robots.txt is a request, not a lock. A crawler can ignore it, and some documented ones do. What stops a crawler is the Block or Challenge action on this page. A User-Agent is also only a claim: use Verified crawlers only to tell the real ones from imitations (only possible where the operator publishes a way to check).

Posture notes

Informational

Observations about this setup. They are not part of the Security Overview score and change nothing.

    Where this runs in the request path

    1. Access rules (blacklist, whitelist, auto-ban), then the Rules engine. These come first, so a rule can still block a crawler.
    2. Generated /robots.txt and /llms.txt answers, then client certificate, path rules and header rules.
    3. AI crawler policy: block, challenge, rate limit, or mark the crawler as allowed.
    4. Bot rules and the AI crawlers switch of the rule: an allowed crawler is not stopped by the AI list of these two, the rest of them still applies.
    5. WAF: an allowed crawler is still inspected, unless you ticked the WAF skip and it was verified. Then the rate limit of the rule, CAPTCHA gating and sign-in, which are unchanged.
