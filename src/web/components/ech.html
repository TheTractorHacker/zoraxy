Encrypted Client Hello (ECH)

ECH hides the host name a visitor asks for (the SNI) from anyone watching the network: the browser wraps the real name in an encrypted envelope addressed to a generic public name. It needs a TLS 1.3 HTTPS listener, an HTTPS (type 65) DNS record carrying Zoraxy's key on every host you protect, and a valid certificate for the public name.

LAN / split-horizon DNS: why ECH fails there, and how to fix it

With split DNS your local resolver answers the host name with Zoraxy's LAN address, but a browser may still fetch the HTTPS (type 65) record from a public resolver (built-in "secure DNS" / DNS-over-HTTPS) or from a resolver that forwards it upstream. If that record carries another provider's ECH config (for example Cloudflare's cloudflare-ech.com) or an old Zoraxy key, Zoraxy cannot decrypt it. The browser then falls back to the outer name and rejects the certificate with ERR_ECH_FALLBACK_CERTIFICATE_INVALID.

Fix one of these:

  • At the DNS provider of the zone: turn ECH off there (Cloudflare: SSL/TLS > Edge Certificates > Encrypted Client Hello), or publish Zoraxy's record from step 2 instead.
  • In the LAN resolver: make it answer the HTTPS record itself with Zoraxy's record from step 2, or answer it empty so the browser stops using the public one. The resolver must be the one the browser really asks (see the DoH note below).
  • In the browser: if "Use secure DNS" / DNS-over-HTTPS is on, the browser ignores your LAN resolver. Turn it off, or point it at a DoH server you control.
  • Browsers cache HTTPS records. After changing DNS, restart the browser (or clear its DNS cache) before testing again.

Common LAN resolvers (option names vary by version: check your resolver's documentation or man page for the exact spelling, and test with dig HTTPS host @resolver):

  • Pi-hole / dnsmasq: dnsmasq can serve arbitrary record types with dns-rr=name,65,hex-rdata (the hex is the wire form of the record). To suppress the type, recent dnsmasq versions have filter-rr=HTTPS; look in man dnsmasq for filter-rr to see if yours has it. In Pi-hole add such lines as custom dnsmasq configuration (the place differs between Pi-hole v5 and v6).
  • AdGuard Home: a custom filtering rule such as ||www.example.com^$dnstype=HTTPS blocks only HTTPS lookups for that name. AdGuard's $dnsrewrite modifier can answer other record types; see its documentation for the HTTPS form.
  • Unbound: local-data: "www.example.com. 300 IN HTTPS 1 . alpn=\"h2\" ech=\"...\"" inside a local-zone for the name; older versions only accept the generic TYPE65 \# length hex form. Run unbound-checkconf before reloading.
  • Router DNS: most home routers cannot serve or filter type 65. Use one of the resolvers above, or change the DNS server handed out by DHCP to one that can.

4 Rotate keys, export and import

Rotation and key retention Rotating creates a new active key and keeps the previous one decrypting (decrypt-only) for the retention window, so browsers holding a cached DNS answer still work. After a rotation, update the DNS records in step 2. A retired key is deleted after the retention window; a browser still holding its config is then rejected until its cached DNS record expires.
