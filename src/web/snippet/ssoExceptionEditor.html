How exception rules work

  • Prefix: /api/webhooks matches /api/webhooks and everything below it, but not /api/webhooks-old. The root prefix / is refused.
  • Exact: only that one path (a trailing slash is ignored).
  • Regex: a Go regular expression that must match the whole path, e.g. /api/v[0-9]+/public/.*.
  • IP / CIDR: compared with the client address as seen by the access rule of this proxy rule. Proxy headers such as X-Forwarded-For are only used when the connection comes from a trusted proxy (Trusted Proxies list) and the access rule is set to trust them; otherwise only the TCP peer address counts.
  • Paths are compared case sensitively unless you tick Ignore case. Requests with unusual paths (.., //, encoded slashes or dots, ;, \, double encoding) never match a path rule and are sent through the normal login.
  • Identity headers that the auth provider would normally set (for example X-authentik-* or mapped OAuth2 claims) are removed from requests that skip the login, so the upstream can never see a forged identity.
