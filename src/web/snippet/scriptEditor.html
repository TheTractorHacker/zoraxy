Lua script

Off until enabled. A sandboxed Lua script either serves the response itself (no backend needed, e.g. robots.txt or a custom 403) or hooks the request before it is proxied. It runs after the rule's access list, WAF, rate limit, CAPTCHA and authentication.

Admin-authored code runs inside the proxy
Only the base, table, string and math libraries exist. There is no file, process, network or module access and no load. Every run has a time limit, a memory ceiling and a response size cap. Errors are shown to visitors as 500 with a request id, never the script.
Read: request.method .path .query .args .headers (lower case names) .host .client_ip .rule .request_id .scheme .body (body: handler mode only, 64 KiB max). Answer: set response.status / response.headers["X"] / response.body, or call respond(status, body, content_type) / redirect(url, code). Hook: request_header_set(name, value), request_header_del(name). Helpers: json.encode/decode, base64.encode/decode, hex, url.escape/unescape, crypto.sha256 / hmac_sha256 / equals, time.now / format, kv.get/set/incr/delete (in memory, per rule), log(...), Lua patterns (string.find/match/gsub).
