# Why was this blocked? (Statistics > Blocked)

From a visitor's 403 (or an admin's hunch) to the rule that fired and a previewed, undoable fix, without a new menu item or page.

* **Reference ID.** Block pages show `ZX-XXXX-XXXX` and send `X-Zoraxy-Ref`. The Blocked tab search box, the Ctrl+K palette and the Status "Blocked today" tile ("See why") all lead to it. A typed Reference ID (`ZX-` + 8 characters) or a full IP address is looked up with `GET /api/blocked/lookup`; anything else filters host, path and rule as before. A found ID shows as a removable tag and opens the drawer; a missing one shows the "No block with this ID" state (the log keeps the last N entries; logging may be off) with a link to the log settings.
* **Table.** User-Agent column (hidden under 900px, full text in the tooltip and the drawer), the Reference ID under the time, the reason chip plus the category as a link to the rule, and a "Why" chevron button on every row (keyboard path to the drawer). The Top IPs card is hidden while it would list one address.
* **Drawer** (`ZxUI.drawer`). Sentence from `/api/blocked/explain` (English text from the server), the fix choices as radios with risk and scope badges, the live preview line and the before/after list, then the details. Apply stays disabled until a choice is made; a fix that changes all sites needs an extra checkbox and is never preselected. Apply sends the `previewId` of the shown preview; a stale preview is refused and reloaded. Success closes the drawer and shows an Undo toast for 15 seconds (with a History link); the change is recorded in History. "Open rule" jumps to the page that owns the rule.
* **Bot rules page.** One read-only line when a rule's action is Challenge and no site has a working CAPTCHA (`CaptchaSites` of `GET /api/botrules/get`).
* **Not done.** A per-site "allow this User-Agent" exemption (botrules has none; "turn bot rules off for this site" is offered instead), localised sentences (the explanation text is English), request simulator, hit counters.
