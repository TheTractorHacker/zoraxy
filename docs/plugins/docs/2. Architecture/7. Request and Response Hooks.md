# Request and Response Hooks

Capture modes hand a whole request to a plugin. **Hooks** let a plugin act as a middleware / WAF style *filter* instead: Zoraxy asks the plugin about a request, the plugin answers with a small verdict (allow, deny, modify, capture), and Zoraxy continues with the (possibly modified) request. Plugins without a `hooks` block in their introspection keep working exactly as before.

Hooks API version: **1** (`zoraxy_plugin.HookAPIVersion`). All new fields are optional, older Zoraxy versions ignore them.

---

## Stages

| Stage | Runs | Typical use |
| --- | --- | --- |
| `pre_auth` | right after the access rules (blacklist / whitelist), **before** WAF, exploit detection, rate limit, CAPTCHA and authentication | bot filters, geo / header rules |
| `post_auth` | after authentication, where the legacy capture plugins run | per-user logic, `capture` |
| `response` | just before the response headers of a proxied response are sent to the client | add / replace / remove response headers |

Legacy `DynamicCaptureSniff` plugins always run at `post_auth`. At `post_auth`, filter plugins run first, then the legacy static and dynamic capture.

The `response` stage covers every response of the HTTP proxy rule, including the pages Zoraxy itself answers with (WAF block page, CAPTCHA, login redirect). The plugin sees the status code and can decide. Body rewriting is not possible. The default site (root endpoint) has no plugin chain, so no hooks run there.

## Introspection

Add a `Hooks` block to `IntroSpect`:

```go
Hooks: &plugin.HookSettings{
    Version:            plugin.HookAPIVersion,
    Stages:             []plugin.HookStage{plugin.HookStagePreAuth, plugin.HookStageResponse},
    FilterRequestPath:  "/filter",   // called for pre_auth and post_auth
    FilterResponsePath: "",          // optional, defaults to FilterRequestPath
    Priority:           10,          // lower runs first
    TimeoutMs:          500,         // default 2000, capped at 10000
    FailurePolicy:      plugin.FailureOpen, // or plugin.FailureClosed
    BodyPreviewBytes:   0,           // 0 = never send a body, max 65536
    BodyContentTypes:   nil,         // e.g. {"application/json", "text/*"}
},
```

JSON (`hooks` key): `version`, `stages`, `filter_request_path`, `filter_response_path`, `priority`, `timeout_ms`, `failure_policy`, `body_preview_bytes`, `body_content_types`.

Invalid parts are dropped and logged (unknown stages, unsafe paths, a hooks version newer than Zoraxy supports).

## Wire format

Zoraxy sends `POST <FilterRequestPath>` with headers `Content-Type: application/json`, `X-Zoraxy-RequestID` and `X-Zoraxy-Plugin-Token`, and the body:

```json
{
  "version": 1,
  "stage": "pre_auth",
  "request_id": "6b72bb99-d3c9-4012-8f75-188a3beb5c8b",
  "request": { "method": "POST", "url": "...", "header": {"User-Agent": ["..."]}, "client_ip": "203.0.113.7", "host": "...", "request_uri": "/login" },
  "body_preview": "<base64>",
  "body_truncated": true,
  "response": { "status": 200, "header": {"Content-Type": ["text/html"]} }
}
```

`request` is the same object the sniff endpoint receives (`client_ip` is the trusted-proxy resolved address). `body_preview` is only present if the manifest asks for it, the method is POST / PUT / PATCH / DELETE and the request `Content-Type` is in `BodyContentTypes` (wildcard-everything is not accepted). `response` is only set at the `response` stage.

The plugin answers `200` with:

```json
{ "version": 1, "action": "deny", "reason": "bad bot",
  "deny": { "status": 403, "body": "Forbidden", "headers": { "Retry-After": "60" } } }
```

| `action` | Meaning |
| --- | --- |
| `allow` | continue |
| `deny` | answer the client with `deny` (status 400-599, default 403, body up to 64 KiB, safe headers only) |
| `modify` | apply `modify`, then continue |
| `capture` | `post_auth` only: proxy the whole request to `DynamicCaptureIngress`. At `pre_auth` it is ignored (it would skip authentication) |

`modify`:

```json
{ "action": "modify", "modify": {
    "request_headers":  { "set": {"X-Score": "3"}, "add": {}, "remove": ["Cookie"] },
    "path": "/new/path", "query": "a=1&b=2",
    "response_headers": { "set": {"X-Frame-Options": "DENY"}, "remove": ["X-Powered-By"] } } }
```

`request_headers`, `path`, `query` are valid at request stages, `response_headers` only at the response stage. Operations are applied in the order remove, set, add.

### What Zoraxy rejects

A verdict is validated completely before anything is applied. An invalid verdict counts as a plugin failure (see below) and changes nothing.

- Header names must be valid tokens, values may not contain control characters (max 8 KiB), max 32 operations.
- Never modifiable: hop-by-hop and framing headers (`Connection`, `Upgrade`, `Transfer-Encoding`, `Content-Length`, `Content-Encoding`, ...), `Host`, `X-Forwarded-*`, `X-Real-Ip`, `Forwarded`, anything starting with `X-Zoraxy-`.
- `Set-Cookie` can only be *added* in a response, never replaced or removed, so session / SSO cookies set by Zoraxy or the upstream stay intact.
- Rewritten `path` must be absolute, not start with `//`, contain no `..`, `?`, `#`, `\` or control characters (max 4 KiB). `query` max 8 KiB without `?` or `#`. The host is never changeable; the upstream target cannot be influenced.
- `deny` status must be 400-599. Deny headers are limited to a safe list (`Content-Type`, `Cache-Control`, `Retry-After`, `Content-Language`, `WWW-Authenticate`, `Content-Security-Policy`, `Referrer-Policy`, `Expires`, `Pragma`, `X-*`).
- Verdict JSON is limited to 256 KiB.
- `deny` and `capture` are invalid at the `response` stage.

## Ordering and concurrency

- Plugins are ordered by `Priority` (lower first). Ties keep the tag / group order, then globally attached plugins ordered by plugin ID.
- Filter plugins of the same stage are called **concurrently** and all see the request as it was when the stage started (they do not see each other's modifications). Verdicts are then merged in priority order: the first `deny` or `capture` wins, `modify` operations are applied one after another (a later plugin overrides an earlier one on conflict). Plugins cannot see other plugins' verdicts or data.
- Legacy dynamic-capture sniffs stay sequential, first accepted wins.

---

## Timeouts, circuit breaker, failure policy

- Every call has a timeout: `TimeoutMs`, default 2000 ms, capped at 10000 ms. This also applies to the legacy dynamic capture sniff, which used to have no timeout.
- A *failure* is a connection error, timeout, non-200 status, oversized reply or invalid verdict. (A legacy sniff answering a non-200 status is a normal "skip", not a failure.)
- After 5 consecutive failures the plugin is skipped for 30 seconds (circuit breaker). One log line is written when the breaker opens and one when it recovers; after the cooldown a single probe request is let through.
- `fail_open` (default): failing or skipped plugins are ignored, the request continues.
- `fail_closed`: the plugin must declare it in the manifest **and** the admin must tick "Block requests if this plugin fails" in the plugin list. Without the admin consent the plugin stays fail-open. When it fails (or the breaker is open) Zoraxy answers `503` (`502` at the response stage).

## Attaching plugins to endpoints

- **By tag**: as before, assign the plugin to a tag in the plugin page, give the HTTP proxy rule the same tag.
- **Global**: in the plugin list, enable *Apply to all HTTP proxy rules* (off by default, admin only; a plugin cannot enable it for itself). Static capture paths stay tag-only.
- **Opt out** on an HTTP proxy rule by adding a tag: `no-plugin:<plugin id>` removes that plugin from the rule, `no-global-plugins` removes all globally attached plugins.

---

## Security model

- Zoraxy calls plugins on `127.0.0.1:<assigned port>`, never follows redirects and ignores proxy environment variables.
- On start every plugin receives a random `invoke_token` in the configure payload (`ConfigureSpec.InvokeToken`). Zoraxy sends it in `X-Zoraxy-Plugin-Token` on filter, sniff and capture calls. Verify it with `plugin.NewFilterHandler(runtimeCfg.InvokeToken, ...)` or `plugin.RequireInvokeToken(...)` so other local processes cannot call your endpoints. It is empty when talking to older Zoraxy versions (no check).
- The plugin-to-Zoraxy API key mechanism (`PermittedAPIEndpoints`) is unchanged. The hook settings API (`/api/plugins/hooks/set`) is admin only and not reachable with a plugin API key.
- `X-Zoraxy-RequestID` is generated by Zoraxy per request (it cannot be set by the client) and is the same for every stage and for capture ingress calls.

## SDK helpers

`plugin.NewFilterHandler`, `plugin.Allow()`, `plugin.Deny(status, body)`, `plugin.Capture()`, `plugin.ModifyRequestHeaders(ops)`, `plugin.ModifyResponseHeaders(ops)`, `verdict.WithReason(...)`, `req.HeaderValue(name)`, `plugin.RequireInvokeToken`, `plugin.VerifyInvokeToken`.

```go
http.Handle("/filter", plugin.NewFilterHandler(cfg.InvokeToken, func(fr *plugin.FilterRequest) *plugin.FilterVerdict {
    if botRegex.MatchString(fr.HeaderValue("User-Agent")) {
        return plugin.Deny(403, "Forbidden").WithReason("bot")
    }
    return plugin.Allow()
}))
```

See `example/plugins/filter-example` for a complete pre-auth User-Agent filter with a response header adder.
